# U-Link 企业 IT 版：需求、流程与边界

> 版本：v0.1 方向稿 · 2026-11-05
> 依据：真实客户需求 + 6 家模型会审（`.review/panel-enterprise/out/REPORT.md`）+ 代码审查
> 关联：[PRODUCT-VISION.md](./PRODUCT-VISION.md)（个人/开发者线）、[PUBLIC-EDITION.md](./PUBLIC-EDITION.md)（开源拆分）

## 0. 一句话

**给 20–200 台 Windows 终端的内部 IT：员工发一个 6 位码，IT 用 AI 在自托管 relay 上做“可审计的远程维修”，不靠记 IP、不靠 RDP、不靠看屏幕。**

不是远程桌面，不是向日葵替代品，不是给客户装的远控后门。

## 1. 真实入口（客户现在的做法）

客户现在用的是一个 13 KB 的 .NET WinForms 小工具：

- `SetRdp`：改注册表开 RDP；
- `AddUser`：把域用户加进 `Remote Desktop Users`；
- `GetLocalIp`：显示本机 IP，IT 用 RDP 连。

它只完成了“把门打开”，没有中继、没有验证码、没有审计、没有 AI，且要求员工机器有公网/同网可达。**我们的替代方案必须保住它“双击就能用”的低摩擦，同时把安全、审计、AI 补上。**

## 2. 目标用户

| 优先级 | 用户 | 为什么 |
|---|---|---|
| P0 | 20–200 台终端、1–5 名 IT 的 SMB / 单组织 | 工单重复、要自托管、要留痕；决策链短 |
| P1 | MSP（管多家客户） | 批量/多租户价值大，但客户隔离与误操作责任重，后置 |
| P2 | 个人多机开发者/家庭 | 免费开源 core 的入口，不承担收入目标 |

**不优先**：大型企业（合规/等保/SOC2 门槛）、纯 C 端（免费远控已足够）。

## 3. 标准工单流程（员工出码，IT 审批）

```
员工微信: "打印机坏了"
   │
   ├─ IT 发 U-Link 员工端（签名 exe/msi）
   ├─ 员工双击 → 托盘显示 6 位验证码 + 设备名 + "仅本次授权"
   ├─ 员工把码发回微信
   ├─ IT 在 CLI/控制台输入: ulink pair approve 384920
   ├─ 员工端显示"IT 已连接，本次会话 30 分钟"
   ├─ IT 的 AI（Claude/Codex/DSH）通过 ulink MCP 诊断:
   │    spooler / 打印队列 / 驱动 / 端口 / 共享 / 事件日志 / 服务
   ├─ AI 给出方案 → IT 预览 → 执行 recipe（需管理员时走 helper/UAC 同意）
   ├─ AI 验证结果 → 解决 / 标记 needs_screen 转人工
   └─ 会话结束 → 审计导出 → 验证码/授权自动失效
```

关键点：

- **员工出码，IT 审批**；v0.2 是反的（IT 出码、员工输码），**v0.3 已补反向流程**（`TypeEnrollCode/Approve/Approved`，已端到端测试）。
- **验证码 ≠ 管理员授权**：码只代表“员工同意连接”；执行管理员操作需要第二次授权（helper/UAC），并记录。
- **会话有时限、有目的、可随时终止**；不是永久后门。
- **AI 先只读诊断，再预览变更，再执行**；高危操作默认人工确认。

## 4. 企业 v1 必须有（按会审共识）

### 4.1 身份、同意、会话

- 员工端一次性 6 位码（5–10 分钟、限次、绑定设备公钥）。
- IT 审批后建立**会话**（30 分钟默认，可延长）；员工端可见状态。
- 会话级授权：只读 / 标准维修 / 管理员操作三档。
- 设备/会话/授权可随时吊销；离职/换机可移除。

### 4.2 受控管理员提权（没有它，打印机/共享/驱动全废）

- **不允许 UAC bypass**，不允许 agent 长期以管理员运行。
- v1 推荐：随安装包注册一个 **U-Link Helper 服务**（SYSTEM），只执行白名单 recipe；agent 通过本地命名管道调用，带设备签名 + 会话授权 + 审计。
- 备选（试点）：每次操作由员工在 UAC 弹窗点“是”；适合有员工在场的场景。
- Helper 的能力边界：打印机、共享、驱动、服务、软件安装、系统设置；**不提供任意 PowerShell**。
- 所有 helper 操作写审计（谁、哪台、哪条 recipe、参数、结果、耗时）。

### 4.3 审计与最小 RBAC

- 命令/recipe 级审计：操作者、设备、会话、参数、退出码、前后状态。
- 日志本地 JSONL + 可选 Syslog/S3/HTTP 导出；企业可接自己的 SIEM。
- v1 RBAC：admin / technician / viewer；MSP 多租户后置。
- 审计里不写凭据、不写文件内容；敏感参数打码。

### 4.4 自托管部署包

- Relay：Docker Compose 一键起（TLS、token、数据卷、健康检查）。
- 员工端：签名 exe/msi；安装/卸载/升级/开机自启；显示验证码。
- IT 端：`ulink` CLI + MCP（Mac/Win/Linux）；可选轻量 Web 审计页。
- 升级/备份/卸载文档；离线安装包（企业内网）。
- 验收：一台干净 Linux VPS 10 分钟内起 relay；干净 Win11 双击装员工端、5 分钟内出码。

### 4.5 高频维修 recipe（5–8 个，先窄后广）

每个 recipe 必须有：检测、动作、结果验证、失败交接、可回滚、`needs_admin`/`needs_screen` 标记。

1. 打印机：列出队列/端口/驱动；添加本地/网络打印机；清理卡死队列；重装驱动。
2. 网络共享：列出共享/映射；创建/删除共享；授权；映射盘符；检查 445/防火墙。
3. 驱动：`pnputil` 列/装/卸；设备管理器异常设备；回滚。
4. 软件：`winget`/MSI 安装/卸载；版本检查；静默参数。
5. 系统诊断：事件日志、服务、磁盘、内存、网络、启动项。
6. 网络：DNS/网关/代理/端口连通性；修复前先确保不会切断 agent 通道。
7. 显示/外设：分辨率、默认打印机、USB 设备（只读为主）。
8. 账号/权限：本地管理员、共享权限（高危，需二次确认）。

## 5. 屏幕：v1 不自研，先做“可交接”

会审结论：**屏幕是门票，不是差异项；v1 不自研推流。**

- CLI + AI 能覆盖约 70–80% 的确定性工单：打印队列、spooler、驱动包、SMB、服务、事件日志、网络。
- 必须屏幕/人工的场景：厂商安装器 GUI、UAC 安全桌面、打印机向导、错误弹窗无错误码、显示/多屏、BIOS/黑屏。
- v1 策略：
  - recipe 显式返回 `needs_screen` / `needs_user_click`，AI 停止并交接，不假装能修。
  - 可选 **截图**（只读）帮助判断；不做实时控制。
  - 屏幕控制转接现有工具（RustDesk/向日葵/RDP），或企业版 v1.5 再评估集成（注意许可证）。
- 不自研 WebRTC/RDP 推流；那会把团队拖进 RustDesk 的战场。
- **长期方向（不阻塞 v1）**：U-Link 增加「视觉 + 输入」两条通道，做成外置 **KVM 节点**（HDMI 采集 + USB HID 注入），覆盖机器没进操作系统时的 BIOS/黑屏场景；硬件不自研，用 PiKVM/NanoKVM 等开源节点。详见 [REMOTE-KVM-NODE.md](./REMOTE-KVM-NODE.md)。

## 6. 架构

```
员工 Windows                         企业自托管
┌─────────────────────┐              ┌──────────────────────┐
│ U-Link Agent (user) │──wss 出站──▶│ Relay (Docker/TLS)   │◀──wss── IT CLI/控制台
│  - 显示 6 位码       │              │  - 设备/会话/审批     │        - Claude/Codex/DSH
│  - 只读诊断          │              │  - 审计/策略          │        - MCP/JSON
│  - 调 Helper         │              │  - 无入站端口         │
└─────────┬───────────┘              └──────────────────────┘
          │ 本地命名管道（签名+会话授权）
┌─────────▼───────────┐
│ U-Link Helper(SYSTEM)│  只执行白名单 recipe：打印机/共享/驱动/软件/服务
│  - 审计/回滚         │
└─────────────────────┘
```

- Agent 普通用户运行，负责出码、只读诊断、转发 recipe 请求。
- Helper 安装时由管理员授权一次，之后只执行白名单；不接受任意命令。
- Relay 单租户（一个企业一套）；MSP 多租户是私有企业版功能。
- AI 侧只连 CLI/MCP，不直接连 relay；权限在 relay/helper 双重校验。

## 7. 开源与商业边界

- **公开 core（Apache-2.0）**：agent、relay、协议、配对/密钥、CLI、MCP、基础审计、recipe 格式、示例 recipe、部署 compose。
- **私有企业版（商业许可）**：企业控制台、RBAC/SSO/AD、多租户/MSP、策略引擎、审计导出/SIEM、屏幕/截图增强、品牌定制、签名安装包流水线、SLA/定制开发。
- 详见 [PUBLIC-EDITION.md](./PUBLIC-EDITION.md)。

## 8. 路线图与验收

### v0.3（企业试点，1 家）

- ✅ 员工出码 / IT `pair approve` 反向流程；设备密钥/吊销。
- ✅ 文件根目录限制；TLS 证书 pin；命令脱敏；结果按设备绑定。
- ✅ 9 个 Windows recipe 骨架（含 screenshot 只读截图）。
- ⬜ 会话时限/授权分档（当前是持久设备授权，非会话租约）。
- ⬜ Helper 服务（SYSTEM 白名单提权）；试点可临时以管理员运行 agent。
- ⬜ 审计集中导出、最小 RBAC、Web 控制台。
- ✅ 自托管 compose + 员工端 exe + CLI；未签名试点（SHA256）。
- 验收：3 个真实工单端到端解决；员工 5 分钟内出码；IT 10 分钟内接入；审计可回溯。

### v0.4（可交付企业）

- 5–8 个 recipe；截图；会话录制（可选）；Syslog/S3 审计。
- 签名 exe/msi + Defender 误报申诉；升级/回滚。
- 轻量 Web 控制台（设备/会话/审计）；RBAC 三角色。
- 验收：干净 Win11 + Defender 开启可安装；断网/重启/改网络后可恢复；审计可导出。

### v1.0（商业化）

- 多租户/MSP、SSO、策略、屏幕转接/集成、移动端（可选）。
- 定价：core 免费；企业版按年/设备/定制开发；手机 App 收费后置。

## 9. 风险与硬约束

| 风险 | 处理 |
|---|---|
| Defender/EDR 误杀（远程 exec + 自签 + 出站，像 RAT） | 代码签名、微软误报提交、真实 EDR 环境测试、提供哈希/安装说明；不承诺“签名即放行” |
| UAC/提权 | Helper 服务合法安装；不使用 bypass；员工可见授权 |
| 滥用/假 IT 钓鱼 | 员工出码 + IT 审批 + 短 TTL + 限次 + 设备绑定 + 审计；企业可加 IP/域名白名单 |
| 维修切断通道（改网络/卸驱动/重启） | 操作前检查通道；超时回滚；本地恢复脚本；helper 保留重连 |
| 企业采购 | 自托管、审计导出、最小权限、卸载/数据删除说明；大客户合规后置 |
| 被抄 | 协议层无护城河；护城河是 recipe 质量、企业流程集成、服务与合规 |

## 10. 最刺耳但必须记住的三句

1. **“能远程执行”不是产品；“能修好、可审计、IT 敢担责”才是。**
2. **员工出码 + IT 审批是入口；没有它，方案就退回 13 KB 小工具的水平。**
3. **屏幕可以后置，提权和审计不能后置；否则打印机/共享/驱动全是空话。**
